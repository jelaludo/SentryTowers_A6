Best Practices

How Stalheart consumes models, what an export needs so it drops in without rework, and how we hand feedback back. The solar power export set (assets/solar-power/README-LODS.md upstream) is the reference example: it already follows every rule below.

What the game does with a model

  • Loads plain GLBs with Three.js GLTFLoader (r160), meshopt decoder wired. Every model is packed with gltfpack at release time (-cc -kn -km -ke: meshopt compression, quantised attributes, named nodes, materials and extras kept). Plain GLB is the source of truth; we do the compression, so an upstream meshopt/ copy is welcome but not required.
  • Pins every file by upstream commit hash and sha256 in docs/*.lock.json and re-fetches from that commit. A hand-off is a commit hash plus a folder, never a loose file.
  • Places models by name: pivots, sockets, hidden parts and the nodes a clip drives are all looked up by node name. Names must be stable across damage states and detail tiers of the same module.
  • Swaps detail tiers by camera distance (src/fx/story-base.js): the distance tier loads first and stands until the camera comes within 150 m, then the game tier is fetched and swapped in with hysteresis. From the map and orbit views the whole base is drawn at the distance tier.
  • Batches static tiers by material and instances repeated pieces (island slabs, wall segments), so one material per tier is the cheapest shape.

Export contract (per module)

ItemRule
Units and axesMetres, +Y up, +Z forward, origin on the ground at the plot centre; the same origin in every state and tier of a module.
Self-containedOne .glb per variant, no external buffers or images. Vertex colours or a small palette; no textures unless agreed.
TiersSeparate files, same node names: LOD1 / game for anything the camera can approach, LOD2 / distance merged to one static mesh and one material for the far view. LOD0 / detailed is for recordings only.
Damaged0 to d3 are damage states, not detail. Every damage state exists at every tier it is meant for.
ClipsNamed, either a loop (*_Cycle, *_Idle) or a one-shot (Doors_Open, Tank_Roll_Out) with an explicit duration. Bake nothing that the engine drives (tracking pivots, turrets).
NodesEvery pivot, socket, and part the game may hide has a unique, meaningful name (TURRET_YAW, VEHICLE_03, REUSABLE_BOOSTER). Loader-sanitised names drop dots: DOOR_01_L.001 becomes DOOR_01_L001, so prefer names without dots.
Geometry hygieneNo coplanar floors (z-fighting), no degenerate triangles, hidden internals removed in closed states, consistent winding.
ManifestA manifest.json per module with file, lod, damage_level, bytes, triangles, draw_calls, plot_m, sockets, clips, credit.
READMERuntime contract in a few lines: what each clip does, which nodes the engine may drive, what the plot reserves, any floor heights.

Numbers are targets, not gates. The solar LOD1 at 3,856 triangles and 7 draws and LOD2 at 2,752 and 1 draw are the model answer; the Terraformer and HUGIN pad "game" exports at ~40k triangles are the ones still over budget.

How we give feedback

  • Every asset we take gets an entry in ATTRIBUTIONS.md and a lock file with the commit, path and hash. Ask us for the lock if in doubt which revision is live.
  • Measured numbers, not impressions: triangles, draws and bytes as loaded, fps on the reference phone, and a screenshot from the game's own camera.
  • One request per module, stated as the contract above plus the budget row it should meet, and the game view it is seen from (map, third person, optic).
  • Anything we derive ourselves (a simplified far tier via gltfpack, a packed release copy) is marked derived and never sent back as if it were authored.

Open requests

  2. Robotic assembly line: same, currently 97k triangles at 7.2 MB.
  3. SH02 rocket: a distance tier for the landing island as seen from the map.

Workshop practices

Local working notes from building the asset families. These are our own tricks and limits, not part of the received game developer contract above, which stays verbatim.

Procedural geometry in Blender

  • Author in metres, Z up, −Y forward in Blender; the glTF exporter turns that into the contract's +Y up, +Z forward. Keep the origin on the ground under the standing hip centre in every tier.
  • Build each tier from one shape(lod) function with if lod<2 and if lod==0 gates. Measure triangles after every change; the knuckle and tip spheres on a glove are the usual budget surprise (dropping them from 32×16 to 6×3 segments at the game tier saved a quarter of the whole character).
  • Closed sub-meshes only, then bmesh.ops.recalc_face_normals once on the merged mesh. Plates are rings of a chamfered outline swept through a bevel profile (back, bevel, face, groove, face), so one helper gives bevels, chamfered corners, an inset panel line and bolt positions.
  • Flat-shade end caps and faceted shells; smooth-shade sleeves. Cut faces out of a shell wherever glass sits over it, or the shell shows through the glass.
  • Soft limbs: a tube whose radius is modulated by a few summed sines with amplitude rising toward each end reads as fabric bunching at the joints at no texture cost.
  • Hoses: sample a Catmull-Rom curve, alternate the segment radius for ribs, add a steel coupling at each end.
  • Asymmetry has to be designed in (holster on one hip, wrist panel on one arm, buckles at different heights); mirrored loops produce toys.

Rigid rigs and authored motion

  • Keep one joint table per family and reuse the IK routines; the biped walk, cautious walk, survey, crouch and halt carried over to a 1.35× wider rig unchanged.
  • Bone orientations passed to the pose solver are absolute, so a waist lean and a chest lean do not add. Set the chest to the lean you want.
  • Turn a leg out with a twist about the bone's own axis, not a world yaw, or the thigh skin leaves the knee. Pivot the boot about the same composite rotation you give the ankle so the toe socket stays on the floor.
  • Validate what the brief asked for as numbers: shoulder span, helmet half width against chest half width, support length, knee flexion difference, heel rise, torso lean, elbow range, left/right hand depth difference.

Runtime materials over palette-only GLBs

  • The contract forbids textures in the file unless agreed, so wear lives in the viewer: three 512² tileable noise textures (weave normal, quilt plus wrinkle normal, grime/scratch/brush/dust pack), per-vertex masks from the loaded geometry (part height by skin index, edge curvature from co-located normal divergence, a cheap neighbour cavity term) and a triplanar onBeforeCompile patch.
  • Map triplanar coordinates in bind-pose space (position and normal before skinning) and carry normalMatrix * mat3(skinMatrix) to the fragment stage, or the detail swims as the character moves.
  • Scale check: a weave cell of about 2.5 mm and quilting diamonds of about 3 cm read right at review distance; at 7 mm and 6 cm the suit looked like a basket and a duvet.
  • Scratches need anisotropic noise (long cells one way, short the other); isotropic thresholds give blotches.
  • Keep the palette inside the saturation rule and let metalness and the environment carry warmth; a "brass" under 15% saturation is a warm grey that only reads as brass in reflection.
  • Shader gotchas: append a newline after any prepended header or three's first #define lands mid-line and the material renders nothing; patch, sample and filter are reserved in GLSL ES 3.

Review and measurement

  • Under EffectComposer, renderer.info.render.calls only counts the last pass unless autoReset is off and reset() runs once per frame.
  • Headless SwiftShader returns from gl.finish() immediately; sync a timing probe with a 1×1 readPixels, take the best of several rounds, and repeat the whole run before quoting a ratio: the same v1 page measured 74 to 131 ms on four runs. Report the result as a relative CPU-rasterizer cost of two render paths, never as a frame rate.
  • Full-resolution GTAO doubled the software frame cost; half resolution with six samples and a denoise pass brought it inside the untextured v1 viewer's own run-to-run spread.
  • Review images of runtime materials must come from the browser; Blender renders only show the palette.

Where this approach runs out

Primitive assembly gives clean budgets, stable node names and repeatable tiers, but it struggles with the organic parts of a suit: the fabric between arm and torso, armpits, the way plates sit over soft volumes. EVA-K8 needed two passes to close the gap under the pauldrons: moving the arm joints inward was not enough, the garment itself had to become the wide part (chest half width out to the sleeve, a large quilted underarm volume on the shoulder bone, zero abduction at rest, a filled pauldron with a trapezius slope back to the collar) with the plates widened to sit on it, and the result is still a set of overlapping shells. For the next character family the better pipeline is probably to scan or sculpt each limb and the torso independently, clean and decimate those meshes, and assemble them on the same joint table and node names, keeping the procedural tools for plates, hardware, hoses and the static distance tier.
