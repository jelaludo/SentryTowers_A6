# Yushi045 / Bio-Pearl

有機性資源コンテナ 第045型 — organic-resource container, version 045. Named by jelaludo for ISAO's construction supply chain on remote planets.

## Purpose and appearance

Yushi045 holds dense organic binder concentrate. ISAO combines it with locally collected regolith and mineral aggregate to manufacture foundations, walls and repair material. The 2.84 m wide squat vessel sits on three stout legs and broad feet, with a central gravity-fed stem, forward-facing extraction coupling, side filling port and top service cap. A pale ceramic-colored upper shell contrasts with the armored dark lower bowl.

Eight large shoulder segments show usable capacity from elevated views. A narrow recessed sight chamber shows olive-green slurry behind an optional small glass cover. The liquid effect is a shader-controlled fill boundary with very slight surface movement and circulation while pumping; there is no fluid simulation, refraction, volumetric interior or particle system. Idle storage is still. The inspection window covers the middle of the vessel; the shoulder gauge remains the authoritative full-range indicator.

## Engine contract

Metres, +Y up, +Z toward the sight chamber and dispensing connection. ROOT is at ground level at the plot centre. YUSHI_BODY is the merged opaque body. YUSHI_GLASS is an optional mesh in LOD0/1 and a lookup-only node in LOD2. DISPENSE_VALVE rotates about its local +Z axis from 0 to π/2 for dispensing; its VALVE_HANDLE is static merged geometry in LOD2. There are no baked clips: capacity and valve state are game-driven. Do not drive the distance-tier valve lookup as if it articulates geometry.

The approach marker is an integration starting point, not a collision-checked ISAO docking trajectory. Hoses, fluid transfer, inventory consumption and building-material recipes belong to the game.

## Live capacity adapter

Import createYushiController from runtime.js and pass the game's existing Three.js instance and loaded GLB scene:

```js
import {createYushiController} from './runtime.js';
const tank = createYushiController(THREE, gltf.scene, {
  fill: inventoryFraction, state: 'ready', glass: true
});
tank.setFill(inventoryFraction); // authoritative finite fraction, clamped to [0,1]
tank.setState('dispensing');     // empty, filling, ready, or dispensing
tank.update(elapsedSeconds);    // visual circulation only; does not consume inventory
// On a tier swap, create a controller for the new root with the same fraction/state.
// On removal: tank.dispose(), then dispose the loaded model's geometry/materials.
```

State does not change inventory by itself. Set fill to zero when reporting empty. The viewer's Run flow button changes its demonstration capacity, but the adapter never invents resource transfers. A normalized volume fraction maps to a level height using fraction = 3t² − 2t³ for the ellipsoidal vessel; it is not treated as a linear height percentage. Absolute usable capacity is game-defined.

The GLB contains a custom _YUSHI vertex attribute, loaded by Three.js as _yushi. Its components are role (0 structure, 1 gauge, 2 sight chamber), normalized level coordinate, and local window x. Keep this attribute when repacking. The supplied Meshopt preview preserves it; validate the consuming game's gltfpack output before adopting it. The adapter rejects missing attributes rather than displaying an incorrect static capacity. Without the adapter, the plain material presentation is explicitly a 50% reference pose.

The adapter modifies the standard material shader and shares a uniform block across the tank's opaque surfaces. It supports the provided Three.js r180 viewer; verify integration with the consuming r160 renderer and its material customizations. The optical window is a small alpha-blended surface, with depth writes disabled. Disable it for distant or repeated units. No bloom is required for the gauge to work.

## Instancing, LOD and review

The viewer's 25-container game-tier yard uses two opaque InstancedMesh batches with glass omitted. Safari's renderer counter reports two model draws for the yard, excluding the grid. Capacity is deliberately shared across those instances. Different per-instance inventories require a game-side instanced attribute or another batching policy; separate controller uniforms cannot give different values within one draw.

LOD2 is a static one-draw mesh whose capacity remains shader-driven. It omits glass and valve articulation but keeps node/socket lookup parity. LOD0 is for close shots and recordings; LOD1 preserves the valve pivot. The default contract selection is distance first, approach at 150 m with 20 m hysteresis; tune these provisional thresholds for a container of this size in the actual game camera.

The viewer offers empty/half/full presets, a continuous capacity slider, filling/dispensing preview, pause, optional glass, wireframe, single/25-container views and orbit/sight/overhead/outlet cameras. Changing tiers preserves the current fraction. Model draw counts exclude the viewer grid. No FPS improvement is claimed; game-camera, reference-phone performance, release compression and ISAO docking remain pending.
